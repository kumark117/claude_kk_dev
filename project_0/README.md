# Minimal RAG

A Next.js page sends a question to a FastAPI server. The server finds relevant
text in local files (BM25) and passes it to an LLM: a built-in stub by default,
or an OpenAI-compatible endpoint. The full design is in [SPEC.md](SPEC.md).

## Requirements

- Node.js 26.13.1 (see `.nvmrc`; for example `nvm install` then `nvm use`)
- Python 3.14.4 with `venv`

## Setup

Run these from the project root. First-time setup needs network access.

```
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm ci --prefix frontend
```

`./test.sh` also does this setup when needed.

## Usage

Terminal 1, the backend on port 8000:

```
backend/.venv/bin/python -m uvicorn app.main:create_app --factory --app-dir backend --port 8000
```

Terminal 2, the frontend:

```
npm --prefix frontend run dev
```

Open the address that Next.js prints (normally <http://localhost:3000>) and ask,
for example, "How should I store coffee beans?". With no variables set, the
answer starts with `[stub]` and the matching text from `data/` is listed under
"Sources". An unrelated question shows a fallback answer and "No matching
sources."

If port 8000 is taken, give the backend another `--port` and start the frontend
with `BACKEND_URL` set to match, for example
`BACKEND_URL=http://127.0.0.1:8123 npm --prefix frontend run dev`.

For a production build, use `npm --prefix frontend run build` and then
`npm --prefix frontend start`.

### Documents

The backend reads the `*.md` and `*.txt` files directly inside the documents
folder (`data/`, or `DOCS_DIR`) once, at startup. Restart it after changing
them. Retrieval matches words, not synonyms.

### Using an LLM endpoint

Set `LLM_PROXY_URL` (the API base, including any version path such as `/v1`),
`LLM_PROXY_MODEL`, and `LLM_PROXY_API_KEY` if the endpoint needs a key, in the
backend's environment before starting it. Questions and the retrieved text are
then sent to that endpoint.

## Environment variables

| Name | Used by | Purpose |
|---|---|---|
| `DOCS_DIR` | backend | Documents folder |
| `LLM_PROXY_URL` | backend | Enables proxy mode; API base address |
| `LLM_PROXY_API_KEY` | backend | Optional bearer key |
| `LLM_PROXY_MODEL` | backend | Model name; required in proxy mode |
| `BACKEND_URL` | frontend server | FastAPI base address |
| `NEXT_TELEMETRY_DISABLED` | `test.sh` | Turns off Next.js telemetry |

`.env.example` lists the names. The backend does not load `.env` files, so export
the variables in your shell. Never commit secrets.

## API

- `GET /health` returns `{"status": "ok", "chunks": <count>}`.
- `POST /ask` with `{"question": "..."}` (1 to 1000 characters after trimming)
  returns `{"answer", "sources": [{"file", "text", "score"}], "mode"}`.

The browser calls `POST /api/ask` on the Next.js server, which forwards to the
backend.

## Tests

```
./test.sh
```

It installs dependencies if they are missing or the pinned files changed, then
runs the backend tests, the frontend tests, the Next.js build and the end-to-end
tests, stopping at the first failure. The end-to-end tests start their own
servers on free loopback ports and stop them afterwards. No API key or real LLM
is used, and once dependencies are installed it runs offline.

## Choices made while building

Points that SPEC.md left open:

- An empty `DOCS_DIR` or `BACKEND_URL` is treated as unset.
- A UTF-8 byte-order mark at the start of a document is ignored.
- `.gitignore` lists `.env*` but keeps `.env.example`.
- `next-env.d.ts` is generated by Next.js and is ignored.
- `agentRules: false` stops `next dev` from generating an `AGENTS.md` file.
- `test.sh` tracks installed frontend packages with a copy of
  `package-lock.json` inside `node_modules`.
