# Ask the docs: a minimal RAG app

A Next.js page sends a question to a FastAPI server. The server retrieves
matching text from local files with BM25 and passes it to an LLM: a built-in
stub by default, or an OpenAI-compatible endpoint. See [SPEC.md](SPEC.md).

```
browser → Next.js /api/ask → FastAPI /ask → BM25 over data/ → stub or proxy
```

## Requirements

- Node.js 26.13.1 (see `.nvmrc`) with npm 11.20.0
- Python 3.14.4 with `venv`

## Setup

Run from this directory:

```bash
nvm use
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm ci --prefix frontend
```

## Run

No environment variables are needed. Use two terminals, both in this directory.

Terminal 1, the backend on port 8000:

```bash
backend/.venv/bin/python -m uvicorn app.main:create_app --factory --app-dir backend --port 8000
```

Terminal 2, the frontend:

```bash
nvm use
npm --prefix frontend run dev
```

Open the address that Next.js prints (normally <http://localhost:3000>) and ask,
for example, "How often should I check tyre pressure?". The answer starts with
`[stub]` and lists its sources.

If port 8000 is taken, pass another `--port` to Uvicorn and start the frontend
with `BACKEND_URL` set to match.

Documents are the `*.md` and `*.txt` files directly inside the documents folder.
They are read once at startup, so restart the backend after changing them.

## Environment variables

[.env.example](.env.example) lists the names. The backend does **not** load
`.env` files: export the variables in the shell that starts each process. Never
commit secrets.

| Name | Used by | Purpose |
|---|---|---|
| `DOCS_DIR` | backend | Documents folder (default: `data/`) |
| `LLM_PROXY_URL` | backend | Enables proxy mode; API base address, including any version path |
| `LLM_PROXY_API_KEY` | backend | Optional bearer key |
| `LLM_PROXY_MODEL` | backend | Model name; required in proxy mode |
| `BACKEND_URL` | frontend server | FastAPI base address (default: port 8000 on `127.0.0.1`) |
| `NEXT_TELEMETRY_DISABLED` | `test.sh` | Turns off Next.js telemetry |

In proxy mode the backend posts to `<LLM_PROXY_URL>/chat/completions`.

## API

| Endpoint | Result |
|---|---|
| `GET /health` | `{"status": "ok", "chunks": <count>}` |
| `POST /ask` with `{"question": "..."}` | `{"answer", "sources": [{"file", "text", "score"}], "mode"}` |

Questions are 1 to 1000 characters after trimming (otherwise 422). A failed LLM
request returns 502.

## Test

```bash
./test.sh
```

It installs dependencies if they are missing or their pinned files changed (the
only step that may need the network), then runs the backend unit tests, the
frontend unit tests, a production build and the end-to-end tests. The
end-to-end tests start FastAPI, Next.js and a mock LLM on free loopback ports
and stop them afterwards. No real LLM or API key is used.

A `StarletteDeprecationWarning` about `httpx2` in the pytest output is expected.

Not covered automatically: a real browser (see the manual checks in
[SPEC.md](SPEC.md), section 10) and a real LLM endpoint.

## Choices made while building

Points the specification left open:

- `test.sh` requires exactly the Node.js version in `.nvmrc`. It tries nvm
  first and fails if that version is still unavailable. It does not check the
  Python version, only that `python3` exists.
- A UTF-8 byte order mark at the start of a document is ignored.
- The route handler checks that the request is valid JSON, then forwards the
  original text unchanged.
- The page sends the trimmed question.
- An empty `detail` string from the server is shown as it is.
- `next-env.d.ts` is generated by Next.js and is not committed.
- `next.config.ts` pins the Turbopack root to `frontend/` and sets
  `agentRules: false` so `next dev` does not generate an `AGENTS.md` file.
- Styling is a short inline stylesheet in `app/layout.tsx`.
